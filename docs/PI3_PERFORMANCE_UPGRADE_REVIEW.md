# PI-3 性能与升级演练候选

2026-09-22；基于 `codex/pi3-history-search` 的 `53ebbc0` 存储实现。
本轮只新增离线验证工具，没有修改生产查询或迁移算法。未部署、未连接真机、未调用任何 API。

## 复现工具

- `tests/history-upgrade-benchmark.ts`：显式传 `--baseline=<旧源码导出目录>`，在系统临时目录创建五万条合成数据。不能用修改 schema 版本号的方法伪造旧库。
- `tests/history-private-upgrade.ts`：显式传 `--source=<assistant-memory.sqlite> --baseline=<对应旧源码目录> --expected-version=5|12`。源用 `readOnly` 打开，经 Node SQLite backup API 取得一致性快照；只对新副本操作。没有 dotenv、provider 或 HTTP 调用。参考 [Node SQLite backup](https://nodejs.org/api/sqlite.html#sqlitebackupsourcedb-path-options)。
- 两个脚本都是 opt-in，不被 `tests/*.test.ts` 自动执行。使用 Node 24 `--import tsx`，不要启动业务后端来跑本演练。
- 源码基线：`58e057b` 的完整 `src/` 用于 v12，`2cec2fb` 的完整 `src/` 用于 v5。恢复与拒绝测试调用真实旧版 `ConversationStore`，不是模拟错误码。
- 报告仅记录数量、耗时、大小、校验布尔值；逐行 hash 在内存比较，不打印消息、ID、凭证或摘要正文。临时副本保留，不自动删除。私有输出、备份和导出源码不得加入 Git。

## 五万条合成数据

Windows 本机 Node **v24.19.0**，100 会话；70 主人、20 另一主人、10 访客；中英文、emoji、字面通配符、引号；包括 system 记录。
25 次查询／类别，p95 为升序第 24 个样本，包含首次查询；不是清除操作系统缓存后的冷盘测量。

| 指标 | 实测 |
| --- | ---: |
| 合成消息 | 50,000 |
| 生成耗时 | 1,468 ms |
| v12→v13 迁移（含索引回填） | 2,918 ms |
| checkpoint 后升级前数据库 | 46,301,184 bytes |
| checkpoint 后升级后数据库 | 78,061,568 bytes |
| 磁盘增加 | 31,760,384 bytes（约 68.6%） |
| 删除一个 500 消息会话 | 40.4 ms |

| 合成查询类别 | p50 ms | p95 ms | max ms |
| --- | ---: | ---: | ---: |
| 不存在的长词 | 95.7 | 113.2 | 114.4 |
| 两字中文 | 47.7 | 60.1 | 60.3 |
| 单字面 `%` | 48.9 | 63.0 | 64.0 |
| 常见英文 | 52.7 | 57.7 | 57.7 |
| `100%` | 51.1 | 61.6 | 63.6 |
| 带引号短语 | 63.1 | 92.9 | 98.3 |
| 单 emoji | 49.4 | 63.4 | 64.0 |
| 另一两字中文 | 49.2 | 58.6 | 60.2 |

上述全部返回 `incomplete=true`：无命中触及扫描上限，常见词触及结果上限。不是完整历史检索，不得将空命中说成“以前没有讨论过”。逐次验证扫描 ≤2,000、内容 ≤4 MiB、命中 ≤10，返回仅属于请求的主人。

## 数据与恢复验证

- 合成库：迁移前后原有业务表逐行指纹和计数完全一致，外键／FTS integrity-check 通过。
- 删除 500 条后剩 49,500 条，FTS integrity-check 再次通过。
- v12 真实旧代码拒绝 v13；拒绝前后原有表指纹相同。
- 升级前备份恢复至另一新目录，指纹与备份一致；真实 v12 旧代码能打开，并新建会话。
- 经用户授权读取本机业务库的一致性快照；实际源版本为 **v5**。第一遍要求 v12 时安全停止，没有修改源版本；随后明确采用 v5 基线再演练。
- 私有副本 v5→v13：原有表的**原有列**逐行指纹与计数一致（新增列另由迁移单元测试验证默认值），外键／FTS 检查通过。耗时约 8.2 ms；204,800→299,008 bytes。
- 真实 v5 旧代码拒绝 v13；从升级前备份恢复后可读写 v5。备份可能携带在线进程租约，只在恢复演练副本清除该租约；不清源库租约。校验在旧版启动恢复逻辑之前完成，不能声称旧版启动不会正常更新 interrupted 等运行状态。

## 验收边界与下一步

- 本轮完成离线规模测量与本机私有副本升级／恢复演练，不是 Linux 生产升级批准。
- 未预先约定延迟 SLO，因此不事后按测得数字宣布“SLO 已通过”。同步查询最慢类别 p95 约 113 ms；对话接线前要评估事件循环阻塞与 Linux 低配实例表现，必要时将查询移出语音主循环。
- 时间索引／扫描预算限制不等于 SQLite VM 硬超时。50,000 条样本也不覆盖所有历史分布、超长消息或多租户规模。
- 生产部署仍须在部署时取得 Linux 的新备份，副本演练并保留与旧代码配套的备份。不能拿本机快照替代 Linux 当时的数据状态。
- A4（合法 `guest_room:1` 被过滤）和 H8（控制／格式字符细分）仍为公开待办，本轮未偷偷修改查询契约。
- 对话检索工具、2,000 字符注入与真实模型阅读验收尚未接通。
