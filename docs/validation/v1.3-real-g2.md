## 1. Safety and evidence rules

- Use a synthetic Calendar title, synthetic notes and a harmless fixed-recipient
  email. Never paste access tokens, provider keys, email addresses, transcripts,
  exact coordinates, database paths, session IDs or device identifiers here.
- Record only app/OS version, test time, network class, elapsed time, PASS/FAIL and
  a short sanitized observation. Screenshots and logs remain private and are not
  committed to this public repository.
- A permanent white screen, an unexpected request for the master token, duplicate
  mail/event side effects, a late transcript after pause, or unauthorized input
  takeover is an immediate **STOP/FAIL**.
- A failed Calendar/Email write is not retried blindly. Inspect the durable ledger
  and provider state, then re-preview and obtain a new confirmation.
- The package is personal Private Testing only. Do not submit it for public review
  or distribute a binary tied to the maintainer's backend.
